Evidence-led plan · 2026.08.12

CoCo 下一步，先换底座，再扩自治。

基于 CoCo v0.5.2 代码与发布历史审计，以及对 Xiaomi MiMo-Code 的架构、汉化、TUI、Provider、Memory、Workflow 和工程流程研究。目标不是照搬另一个 Agent，而是让 CoCo 的中文体验、终端设计、安全内核和上游维护形成可持续优势。

Best decision

源码产品层 + 选择性上游 Fork + 持续缩小兼容 Patch

不立即全量 fork，不继续无限扩张编译产物 patch。未来 90 天先统一产品声明、模型生命周期、stable-key i18n 和 TUI primitives。
1111行 artifact patch当前最大维护风险，已经承载品牌、汉化、UI 和 runtime 语义。
0.5.2事实基线Provider seed、installer、bootstrap 和 live runtime 刚完成一次典型统一。
90d强承诺窗口只承诺可以验收的基础迁移，不用一年愿景替代近期执行。
12m战略视野Memory、Workflow、Isolation 在底座门禁通过后逐步启动。

Truth baseline

先看清 CoCo 已经是什么

CoCo 不是一个简单换皮 CLI。它已经拥有安全状态、持久任务、执行证据、Provider 数据治理和严格发布工程。问题不在“能力太少”，而在这些能力与上游 runtime 的所有权边界不清晰。

保留

可靠的本地任务内核

事务状态、PID identity、task event、logs、receipt、cancel、worktree 和 loopback control 是 CoCo 的核心资产。

保留

Fail-closed 安全边界

隔离不可用时拒绝执行，审批不冒充 sandbox；runtime integrity、secret scan 和 package closure 持续作为发布门禁。

重构

产品行为所有权

品牌、汉化、主题、模型 visibility 和 startup 不应继续堆在单个编译产物字符串 patch 中。

风险

多运行时副本漂移

tracked dist、bundled Pi、nested pi-tui、installer、bootstrap 和 live session 曾多次出现状态不一致。

缺口

统一 Provider 生命周期

Seed、catalog、auth、capability、ready、select 和 active 需要一个 reconciliation service。

缺口

可持续上游同步

当前固定 Pi 0.82.1。没有持续 integration branch 和 divergence ledger，升级成本会随定制快速增长。

MiMo-Code study

学方法，不复制产品

MiMo-Code 是 OpenCode 的深度产品 fork。它最值得学习的不是 Logo 或某个颜色，而是把 TUI、汉化、Memory、Provider capability 和 Workflow 当成源码级产品系统。公开快照：main commit 332d7b0，研究日期 2026-08-12。

领域MiMo-Code 已验证做法CoCo 应吸收不能照搬
TUISolidJS/OpenTUI；feature components、dialogs、routes、contexts、UI primitives 分层；visual mode 可切换。源码级组件、语义 token、visibility/renderability 同一 predicate、mouse release gating。默认动画、背景资产、全屏 transcript 和具体视觉品牌。
汉化Typed locale modules；覆盖 en、zh、zht、ja、fr、es、ru；slash command 和 skill 单独本地化。Stable message key、typed schema、fallback、alias/skill 分域、CJK width 测试。只依赖人工发现硬编码字符串；注册 locale 与实际 payload 不一致。
MemoryProject memory、checkpoint、notes、task progress、SQLite FTS5、write-disable。分层记忆、可审计注入、可关闭写入、context budget 和 compaction preservation。一次性引入完整 actor/memory/workflow 复杂度。
ProviderAuth、catalog、capability registry、transform、error、modality 分层；models.dev 提供 metadata。可见不等于 ready；能力、协议、reasoning、modality、转换和 retry 独立表达。小米 OAuth、托管服务和 MiMo 专属路由。
WorkflowActor、child task、deterministic workflow、worktree、checkpoint 和 lifecycle ownership。先确定性 workflow，后受控自治；角色、预算、取消域和结果聚合。无限 swarm、未隔离写并行和过早扩大控制面。
工程源码 monorepo、Oxlint、typecheck、sharded tests、flip-verified safety tests、多平台 binary releases。源码所有权、测试反证、跨平台 smoke、发布产物矩阵。立即复制完整 monorepo 和无人维护的 web/desktop surface。

Operating model

四个方案，只选一个组合

技术路线必须按变化类型决策，而不是宗教式选择“永远不 fork”或“全部 fork”。最佳方案让 CoCo 拥有产品行为，同时继续快速吸收上游安全和功能更新。

不选

继续扩张 Patch

短期最便宜，长期会继续出现副本、anchor 和 live runtime 漂移。

不立即

完整源码 Fork

控制最好，但当前一次性承担整个 Pi runtime 的维护成本过高。

不足

纯 Extension

适合 Provider 和命令，但无法覆盖战略 TUI 和 model runtime 改动。

推荐

混合下游模式

产品源码层承载新能力，选择性 fork 处理核心 seams，patch 退回短期兼容工具。

L1 · COCO SOURCE

Provider、语言、配置、任务、Memory、Workflow、TUI primitives、installer 和 release。

L2 · SELECTIVE FORK

必须进入上游内部的 model runtime、startup composition、TUI registration 和 session lifecycle。

L3 · COMPAT PATCH

版本限定、fail-closed、有 owner、测试和 removal condition 的短期兼容修复。

Product pillars

五条产品主轴

路线图不是按竞争对手功能列表排队，而是围绕 CoCo 的组合优势建立连续能力。

A

中文优先终端体验

Stable-key i18n、简中 100%、繁中 beta、语义主题、CJK/IME/窄屏/256 色正式矩阵。

B

Provider 与模型可靠性

统一 lifecycle、LKG、freshness、health、live probe、capability 和 transform。

C

可恢复长任务

Project memory、session checkpoint、task progress、context budget 和透明注入。

D

可验证工作流

Plan/edit/verify、receipt、deterministic workflow、角色、预算、worktree 和取消域。

E

可持续上游与发布

Weekly intake、monthly merge、product manifest、cross-platform smoke、provenance 和 rollback。

Gated roadmap

六个命名里程碑

不再把未来能力写成 v0.3、v0.4。语义版本只描述实际发布；路线图按门禁推进。12 个月是方向，未来 90 天才是强承诺。

M0

Truth & Freeze

先建立真实能力、Patch 和上游基线。

0-2 周
交付

Patch inventory、capability matrix、旧 roadmap 归档、product manifest RFC、upstream dashboard。

门禁

所有行为有 source-of-truth；新功能不得无审批进入 monolithic patch。

非目标

不在此阶段加 Memory、动画或新 workflow。

M1

Foundation

建立 CoCo 自有源码产品层和统一声明。

2-8 周
交付

CoCo core package、product manifest、Provider lifecycle、统一 state reconciler、Patch 分域。

门禁

新增 Provider/默认模型只改一个声明；bootstrap、install、live session 共享契约。

指标

默认值/Provider 多副本为 0；新 monolithic anchor 为 0。

M2

Language & Design System

中文优先、源码级、可验证的 TUI。

第 2-4 月
交付

全 TUI stable-key i18n、简中 100%、繁中 beta、hardcoded scanner、semantic tokens 和 UI primitives。

门禁

核心翻译不再依赖 regex patch；缺 key、placeholder、width 或 locale payload 时 CI 失败。

矩阵

48/80/120 × dark/light × en/zh × truecolor/256，加 IME、mouse 和 pseudo-locale。

M3

Runtime Ownership

战略 runtime 改动进入选择性源码 fork。

第 3-6 月
交付

Base commit、divergence ledger、model runtime/startup/TUI registration 源码化、monthly merge train。

门禁

核心改动可 typecheck/unit test；artifact patch 缩减至少 60%。

上游

通用修复准备 upstream contribution；CoCo 特有改动保持独立 commit。

M4

Memory & Context

让长任务可恢复、可解释、可控成本。

第 5-8 月
交付

Project memory、session checkpoint、task progress、write disable、本地索引、context budget。

门禁

恢复不覆盖并发用户修改；注入来源可审计；compaction 不丢状态。

实验

冻结任务集 paired 测试成功率、token、latency 和恢复质量。

M5

Controlled Workflows

从多个 Agent 走向受控工作系统。

第 7-10 月
交付

Explorer/Worker/Reviewer、deterministic workflows、child task、budget、wait/cancel 和 aggregation。

门禁

冲突和越界 fail closed；写并行仅限独立 worktree 和 ownership。

默认

Read/test/review 可并行，修改默认单 worker。

M6

Isolation & Distribution

生产级隔离和跨平台发布闭环。

第 9-12 月
交付

Linux bwrap/container、network/secret policy、跨平台 smoke、SBOM、attestation、rollback。

门禁

Escape、symlink、socket、credential、process tree 和资源耗尽攻击测试通过。

诚实边界

macOS/Windows 不虚假宣称等价 sandbox；禁止自动 host fallback。

First 90 days

六个双周 Sprint

前三个月的目标不是交付最多功能，而是让后续每个功能只需要改正确的一层，并能被 CI、真实 PTY 和 packed artifact 验证。

真相和边界

发布报告；冻结大 patch；建立 domain issue、owner 和 upstream watcher。

单一产品声明

Product manifest 生成 version、default、theme、provider 和 release metadata。

模型生命周期

Reconcile API、readiness、health、freshness、LKG 和 live session activation。

i18n 基础

Canonical inventory、stable key adapter、scanner；迁移设置、模型、登录、会话。

TUI primitives

Theme、Dialog、Selector、Message、ToolSurface、Footer、Prompt golden matrix。

选择性 Fork 试点

源码化一个 vertical slice，与 patched runtime 差分验证，输出 burn-down。

Quality gates

用指标阻止路线图变成愿望

每个阶段未过门禁就缩小范围，不把风险滚进下一阶段。外部项目只提供候选方法，CoCo 的发布结论必须来自自己的基线和真实产物。

-60%Patch burn-down

6 个月减少 60%，12 个月减少 85%。

<30dUpstream lag

安全更新即时处理，稳定 baseline 落后小于 30 天。

100%简中覆盖

核心 message key、placeholder 和宽度门禁全部通过。

<1%Readiness 误判

显示 ready 但 minimal live probe 失败率小于 1%。

>95%长任务恢复

且并发用户修改覆盖次数为 0。

0Release escape

Installer、runtime 副本和默认值类 hotfix 目标为 0。

100%Receipt 覆盖

Completed 必须有验证证据或明确 waived reason。

>99%安装成功

支持平台 clean install、upgrade 和 uninstall。

Risk controls

主要风险与制动器

最危险的不是技术做不到，而是同时扩张 fork、Memory、Workflow、UI 和 Provider，导致维护边界再次失控。

Fork divergence

每周 intake、每月 merge、分离 upstream merge 和 CoCo feature commit；记录 base 和 divergence。

Patch drift

Anchor inventory、exact occurrence、fail-closed、domain tests 和 removal condition。

Provider 假就绪

Catalog visibility、auth、capability、probe 和 active 状态分离；失败保留 LKG。

Memory 污染

来源、时间、范围可审计；write disable；用户可清理、导出和禁止自动注入。

TUI 回归

Golden matrix、PTY、IME、CJK、mouse、SSH/tmux/screen 和 reduced motion。

供应链真实性

Immutable assets、attestation、SBOM、source commit 和 build environment 记录。

Non-goals

明确不做

战略需要拒绝列表。以下事项不进入当前 12 个月主线，除非出现新的可验证约束。

大规模 Go/Rust 重写立即复制完整 OpenCode monorepo用动画替代交互质量把 /models 等同可用Guard 冒充 Sandbox隔离失败自动回退 Host无限 Swarm复制 MiMo 品牌与资产

Sources & limits

资料和证据边界

MiMo-Code 研究来自公开仓库快照和提交；未复制其代码、Logo、配色或小米服务。任何未来源码复用必须单独完成 license、NOTICE、attribution 和商标审查。

Final recommendation

先让每个能力有正确的家，再让 Agent 走得更远。

未来 90 天优先完成 CoCo 源码产品层、统一 Provider 生命周期、stable-key i18n、TUI primitives 和选择性 fork 试点。底座门禁通过后，再吸收 MiMo-Code 在 Memory、Context Budget、Workflow 和 Interaction Hardening 上的优秀方法。这样 CoCo 才能既保留本地安全和终端气质，又获得持续产品化和上游演进能力。
