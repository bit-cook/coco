CoCo 下一步怎么做最好？

基于 CoCo v0.2.1 代码审计、IdeaX、pi-codex 与 18 个一手资料方向形成。结论不是继续堆功能，而是把已有本地任务能力升级为可观察、可验证、可恢复、可隔离、受控并行的工程系统。

North star

可靠的本地 Agent 任务系统

Local-first · Observable · Verifiable · Recoverable · Isolated
01先看得见任务事件、心跳、日志、卡住检测和完整执行收据。
02再证明完成计划、修改、验证与失败原因形成强制闭环。
03然后可恢复Checkpoint 与 Git/worktree 对齐，不承诺虚假的全量回滚。
04最后扩自治先沙箱与预算，再开放写密集并行和远程执行。

Truth baseline

先纠正能力事实

旧竞品报告将 MCP、Subagents、Worktrees、后台任务和 VS Code 列为缺失，这已不符合 v0.2.1。规划必须从真实基线出发，避免重复建设。

已具备Durable local tasks

持久 runner、owner lock、取消、PID identity、进程树终止与保守兼容。

已具备MCP 与故障隔离

Registry、审批策略、tool adapter，单 server 启动失败不会拖垮全部服务。

已具备Worktree 与 Subagents

任务 worktree 生命周期和自动加载 subagent 已存在，headless 本地资源信任已收紧。

已具备本机控制面与 VS Code

Loopback token API、Dashboard，以及任务、上下文、history、diff、approval 的 IDE 入口。

真实缺口可观测与验证闭环

缺少统一事件审计、结构化日志、心跳、卡住判定、验证证据和可重放诊断。

真实缺口隔离、上下文与远程工作流

guard 不是 sandbox；尚缺 Repo Map、定向上下文、真实 GitHub workflow 与受控远程执行。

Architecture decisions

采用、延后、拒绝

IdeaX 是假设清单，pi-codex 是交互参考，一手产品资料用于校验边界。任何精确提升比例都必须经过 CoCo 自己的真实任务实验。

决策内容理由与边界落点
采用Append-only 任务事件 + 当前状态快照支持审计和诊断，但不以 event sourcing 替换成熟的 tasks.json 事务模型。v0.3
采用异步 shell session 与增量输出借鉴 pi-codex UX；必须沿用 CoCo 的 PID identity、process-group 与 durable runner 安全边界。v0.3
采用Repo Map + 定向上下文Aider 与 Tree-sitter 支持该方向；先做符号/引用预算实验，不承诺固定性能提升。v0.4
延后Linux OS sandbox / Container provider需独立威胁模型、凭据/网络策略与 fail-closed 可用性探测；先作为可选 provider。v0.5
延后写密集多 Agent 与远程执行只有 worktree、预算、隔离、冲突检测和评测门禁成熟后才开放。v0.6+
拒绝大规模 Go/Rust 重写、无限 swarm、guard 冒充 sandbox没有当前瓶颈证据，且会扩大迁移和安全风险。非目标

Invariants

六条不变原则

这些原则优先于版本日期和功能数量，任一版本违反时不得发布。

本地优先，不偷换云服务

Dashboard 和 runner 仍是本机能力；远程执行必须作为明确的新 trust domain。

审批不等于隔离

策略决定“是否允许”，OS/container 边界决定“实际上能碰什么”。

失败关闭

身份不明、锁状态异常、沙箱不可用、验签失败时不猜测、不降级执行。

证据优于完成宣称

任务完成必须带命令、退出码、测试结果、diff 与未验证项。

并发必须隔离

只读工作可先并行；写工作一任务一 worktree，并设并发、token、时间和进程预算。

渐进迁移

保留 v0.2.1 状态兼容读取；新 schema 版本化、双读验证、可一键回退。

Five gated releases

五阶段版本路线

建议按能力门禁而非日历强推：v0.3–v0.6 的开发窗口约 30 至 38 周；v0.7 条件启动，不计入日期承诺。若门禁未过，缩小范围，不把风险滚入下一阶段。

v0.3

任务可观测与执行证据

先让长任务不会“无声卡死”，用户能看、能停、能诊断。

P0 · 6–8 周
范围

先冻结事件协议：单 task/run writer、单调 seq、eventId 幂等、snapshot 提交顺序、尾部半写恢复和 artifact 引用；再交付非交互式增量日志、heartbeat、只读 Dashboard、取消诊断与 execution receipt。

非目标

不做可输入 shell session；不重写 tasks.json；不做 WebSocket 必选依赖；不开放远程控制；不改变现有 fail-closed 终止语义。交互式 shell 延后到 v0.3.x 实验。

退出门禁

半写、重复提交、各崩溃点和并发写入故障注入全部通过；日志可断点续读；取消后无遗留进程树；固定负载矩阵中不重复启动。

v0.4

上下文与验证闭环

减少盲目全库读取，并让“完成”对应可复核证据。

P0 · 8–10 周
范围

首版限定 JavaScript/TypeScript：Tree-sitter 符号清单、按预算的文件/符号选择；plan→edit→lint/test→review 状态机；验证策略模板；失败分类。暂不承诺通用跨语言引用图。

执行边界

验证命令仅运行于显式模式：isolated-required 在隔离能力缺失时拒绝；host-explicit 仅用于可信本地项目并持续标注“非隔离”。禁止隔离失败后自动回退 Host。

实验与门禁

30–50 个任务仅作试点；冻结任务、判题、模型、工具、预算和环境，按任务报告 paired 结果。默认开启要求成功率和错误修改率不退化、关键上下文召回率过线、token 中位数达到首轮基线后校准的决策阈值。

v0.5

Checkpoint 与执行隔离

恢复必须诚实，沙箱必须由 OS 强制，而不是命令字符串判断。

P0/P1 · 8–10 周
范围

Git-aware checkpoint；恢复预览；dirty/untracked/concurrent edit 防护；完善 ExecutionProvider；Linux bwrap/container 后端；网络/凭据/资源策略。

安全边界

isolated-required 默认 workspace-write、网络关闭、秘密显式 deny/mask，能力缺失即拒绝；host-explicit 必须由用户或项目显式选择并持续标注“非隔离”。任何模式都禁止自动降级。

退出门禁

逃逸测试、symlink/path traversal、socket/credential、进程树和资源耗尽测试全部通过；恢复不覆盖并发用户改动；macOS/Windows 不虚假宣称同等隔离。

v0.6

受控并行编排

把现有 subagent 和 worktree 连接为有预算、有角色、有冲突边界的工作流。

P1 · 8–10 周
范围

Explorer/Worker/Reviewer 角色；父子 task event；每 worker 独立 worktree；并发、token、时间、进程预算；失败传播、取消与结果聚合。

默认策略

探索、测试、审查可自动并行；修改默认单 worker；多 worker 写入仅在文件所有权可静态分区且用户显式启用时开放。

退出门禁

相对单 Agent 的墙钟、成功率、冲突率与总成本采用预注册 paired 实验和置信区间判断；25% 增速、2pp 回归、60% 成本为初始决策阈值，首轮冻结基线后校准。冲突或越界写入必须 fail closed。

v0.7

GitHub 原生工作流与可选远程执行

先把本地可靠内核接入团队工作流，再决定是否建设托管控制面。

P2 · 条件启动
范围

Issue/PR 触发、专用分支、checks、artifact、review receipt；OIDC/trusted publishing；可选 ephemeral runner adapter；审计导出。

非目标

不自动 merge；不跨仓库写；不长期保管用户 PAT；不默认联网；不把本机 Dashboard 直接暴露公网。

启动条件

v0.3–v0.6 SLO 连续两个版本稳定；明确 GitHub 权限与 OIDC 约束、runner 镜像/补丁责任、日志保留和 incident owner；威胁模型通过外部审查且有真实团队需求，否则只交付 GitHub Action。

Quality gates

指标、评测与停止线

公开 benchmark 只回答一部分问题。CoCo 必须同时测真实仓库成功率、运行可靠性、安全边界、成本和用户等待体验。

500 runsRunner 故障注入

每个支持平台的固定 OS/Node/负载矩阵连续运行；重复执行和错误终止必须为 0，恢复率阈值在基线后以置信下界定义。

100%完成证据覆盖

completed 必须具备验证 receipt；无法验证则是 waived，不伪装成功。

3 axes卡住检测质量

同时报告误报率、漏报率和检测延迟；基于心跳、输出、进程状态与等待原因，不用单一固定超时。

100%安全套件通过

已定义安全回归套件全部通过且阻断级漏洞为 0；未知覆盖范围不作安全宣称。

30–50试点任务样本

覆盖 bugfix、跨文件功能、测试、重构、文档与长命令；仅用于校准，不单独支撑默认开启结论。

Paired统计判定

冻结任务、模型、工具、提示和预算，报告 paired 结果、置信区间、类别分层与失败分类。

门禁GoNo-Go / 回退

质量冻结任务集的 paired 结果足以排除预注册回归幅度，且失败可诊断。置信区间无法排除回归或错误修改率上升，默认关闭并保留实验开关。

Data & API

最小数据演进

不把所有状态一次性改成事件溯源。保留当前快照为执行真相，增加可校验的事件和产物层。

对象最小字段兼容策略
Task snapshotschemaVersion, taskId, revision, owner, state, processIdentity, heartbeatAt, activeRunId原子写；旧 v0.2 状态只读迁移，缺 identity 时保持保守行为。
TaskEventeventId, seq, taskId, runId, traceId, parentId, type, at, actor, payloadRef, payloadDigest单 writer、append-only、eventId 幂等；尾部半写可恢复，未知事件可跳过但不得改写历史。
Artifact / Receiptkind, path/ref, sha256, producerRunId, command, exitCode, startedAt, endedAt, verdict大日志分块保存，事件只存引用与摘要；默认脱敏。
Control API/tasks/:id/events?after=, /runs/:id/logs?cursor=, /runs/:id/input, /runs/:id/cancel保持 loopback + token；分页/游标有上限；不增加公网监听选项。

Risk register

主要风险与缓解

最危险的不是延期，而是在没有证据时扩大自治和权限。

状态双真相

事件与快照漂移。缓解：快照维持执行真相，事件带 revision/seq；CI 做重建对账但不以重放驱动生产执行。

日志与隐私泄露

命令输出可能含 token。缓解：采集前脱敏、大小/保留期限制、导出二次确认、凭据字段永不写事件。

沙箱兼容性与虚假安全

bwrap/container 在部分环境不可用。缓解：能力探测、明确模式标签、严格模式 fail-closed、平台级测试矩阵。

并行成本失控

更多 Agent 不等于更快。缓解：默认只读并行、预算上限、早停、对照单 Agent，未过阈值不默认开启。

上游 Pi 漂移

CoCo 是下游发行版，私有分叉会增加维护面。缓解：薄集成层、契约测试、逐版本兼容审计，不为追新强升。

路线过载

同时做 UI、云、沙箱和索引会稀释质量。缓解：每阶段最多一个核心用户结果；No-Go 时删范围而不是降门槛。

Final recommendation

如果现在只做一件事

先交付 v0.3 的事件协议 + heartbeat + 非交互增量日志 + stuck diagnosis + execution receipt。它直接解决长任务“是否还活着、做了什么、为何失败、能否安全停止”，并为之后的验证、恢复、沙箱、并行和 GitHub 工作流提供共同地基。交互式 shell 不挤入首版；发布签名与文档纠偏作为并行 P0。
