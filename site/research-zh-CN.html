吸收机制，保留边界。

我们在固定源码提交上检查了 Prime Agent 与 DeepSeek Harness，寻找能够增强 CoCo 的设计。本文不是集成公告：没有引入外部 runtime、源码或依赖。

总体决策

采用契约，不导入框架。

CoCo 只通过自己的持久化、授权、containment、完整性和测试边界重新实现经过选择的机制。

Prime Agent

能够继续，也能够恢复。

Prime Agent 分离 client、daemon supervisor、worker、root/child session、durable JSONL/artifact state 和持久 Python 执行。最值得学习的是恢复所有权与继续策略，而不是 Python runtime 本身。

01

命令恢复 journal

执行前持久化 command receipt，响应前持久化 result。重复 ID 返回 durable result，未知副作用不能盲目重放。

02

Worker generation fencing

恢复 worker 使用新 generation；旧 worker 无权提交结果，中断工作保持可观察。

03

Steering / follow-up 双队列

Steering 在在途 tool 边界后进入；follow-up 只在 Agent 原本准备停止时进入。

04

权威 lineage

Parent-child topology 属于 supervisor 的 append-only ledger，不能从对话文本反向推断。

DeepSeek Harness

每个副作用都从持久证据开始。

DeepSeek Harness 把 turn、模型输入、tool call、result 和 stop reason 建模为 durable event。最有价值的模式，是让模型请求和每个外部副作用都可重建。

01

模型输入 ledger

模型看到的每个 byte 都必须从 durable session state 重建，并与真实 request projection 比较。

02

Durability fence

调用 provider、shell 或 MCP 前先持久化 intent。持久化失败时，外部调用不能开始。

03

有界有序 tool pool

只有显式声明 safe 的工具可以并行；exclusive 工具形成 barrier，结果按请求顺序提交。

04

已验证 generation

Provider、credential、configuration 和 MCP 变更原子发布；在途工作继续绑定原 generation。

采用边界

有价值，不等于兼容。

功能评分不能抵消授权、provenance、containment 或恢复缺口。外部机制只有通过 CoCo 自己的生产门禁才会被采用。

通过 CoCo 契约吸收

  • Command recovery 与明确 uncertain 结果
  • Model-visible-means-logged 证据
  • 外部副作用前 durability fence
  • 有序 safe-tool 并行
  • Provider 与 MCP generation snapshot
  • Last-good configuration 与 revision 检查
  • 权威 Agent lineage

拒绝或暂缓

  • 整体迁移 Cordis 或外部 runtime
  • Secret 与进程隔离前引入持久 Python
  • 无认证 LAN Control
  • 把文件 sandbox 当完整安全边界
  • 无授权的 global harness 修改
  • 无逐次同意和有界脱敏的 trace upload
  • 无预算的递归 Agent
