Prime Agent

Durable work that can continue.

Prime Agent separates clients, a daemon supervisor, workers, root and child sessions, durable JSONL/artifact state, and persistent Python execution. The strongest lessons are about recovery ownership and continuation, not the Python runtime itself.

01

Command recovery journal

Persist command receipt before execution and result before response. Duplicate IDs return durable results; uncertain side effects are never blindly replayed.

02

Worker generation fencing

Recovered workers receive a new generation. Stale workers cannot publish results, and interrupted work remains observable.

03

Steering and follow-up queues

Steering enters after an in-flight tool boundary; follow-up enters only when the agent would otherwise stop.

04

Authoritative lineage

Parent-child topology belongs to an append-only supervisor ledger instead of being inferred from conversational text.

DeepSeek Harness

Every effect starts from durable evidence.

DeepSeek Harness treats turns, model inputs, tool calls, results, and stopping reasons as durable events. Its most valuable patterns make the model request and every external effect reconstructable.

01

Model-input ledger

Every byte visible to the model must be reconstructable from durable session state and checked against the real request projection.

02

Durability fence

Persist model or tool intent before invoking a provider, shell, or MCP. If persistence fails, the external effect does not begin.

03

Ordered bounded tool pool

Only declared-safe tools run in parallel. Exclusive tools form barriers, while results commit in request order.

04

Validated generations

Provider, credential, configuration, and MCP changes publish atomically; in-flight work remains bound to its validated generation.

Adoption boundary

Useful does not mean compatible.

Feature scores cannot compensate for missing authorization, provenance, containment, or recovery. CoCo accepts mechanisms only when they pass its own production gates.

Adopt through CoCo contracts

  • Command recovery with explicit uncertain outcomes
  • Model-visible-means-logged evidence
  • Durability fences before side effects
  • Ordered safe-tool parallelism
  • Provider and MCP generation snapshots
  • Last-good configuration with revision checks
  • Authoritative agent lineage

Reject or defer

  • Wholesale Cordis or runtime migration
  • Persistent Python before secret and process isolation
  • Unauthenticated LAN control
  • File sandbox presented as a complete boundary
  • Global harness mutation without authorization
  • Trace upload without consent and bounded redaction
  • Unbounded recursive-agent budgets

CoCo route

Research became explicit work.

The findings were translated into owned work packets rather than copied implementation. Their dependencies preserve CoCo's release, recovery, and containment foundations.
