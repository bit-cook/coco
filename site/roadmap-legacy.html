Historical snapshot · CoCo v0.2.1

可靠的本地 Agent 任务系统

旧版路线图基于 CoCo v0.2.1、IdeaX、pi-codex 和 18 个一手资料方向形成，核心路径是：先可观察，再可验证，然后可恢复和隔离，最后扩展受控并行与 GitHub 工作流。

历史归档

该方案保留用于与 2026-2027 新战略对比。它不是当前执行路线，也不代表 v0.5.2 的能力状态。原路线使用 v0.3-v0.7 预测功能，后来与真实发布版本线发生错位。

Original thesis

四步核心决策

旧研究认为 CoCo 已具备 durable tasks、MCP、worktree、subagents、本机控制面和 VS Code；真实缺口集中在统一可观测、验证闭环、checkpoint、OS 隔离、上下文和受控远程工作流。

01 · 先看得见

任务事件、heartbeat、增量日志、卡住检测和完整执行收据。

02 · 再证明完成

Plan、修改、lint/test、review 与失败原因形成强制闭环。

03 · 然后可恢复

Checkpoint 与 Git/worktree 对齐，不承诺虚假的全量回滚。

04 · 最后扩自治

先沙箱和预算，再开放写密集并行和远程执行。

不变原则

Local-first、fail-closed、审批不等于隔离、证据优于完成宣称。

明确拒绝

大规模 Go/Rust 重写、无限 swarm、guard 冒充 sandbox。

Five gated releases

原五阶段路线

原计划以版本号绑定未来能力。新版已改用命名里程碑，因为真实 `0.3.x-0.5.x` 发布了不同范围，版本预测不再可靠。

v0.3

任务可观测与执行证据

事件协议、非交互增量日志、heartbeat、Dashboard、取消诊断和 execution receipt。

P0 · 6-8 周
边界

不重写 tasks.json，不做 WebSocket 必选依赖，不开放远程控制。

门禁

半写、重复提交、崩溃点和并发写故障注入通过；取消后无遗留进程树。

后续事实

Task events、logs、receipts 和 diagnosis 已在后续 0.3 系列形成实现。

v0.4

上下文与验证闭环

JS/TS Repo Map、按预算选择、plan→edit→lint/test→review 状态机。

P0 · 8-10 周
执行边界

`isolated-required` 不可用时拒绝；`host-explicit` 持续标注非隔离。

实验

冻结任务、模型、工具、预算和环境，报告 paired 结果和失败分类。

后续事实

真实 0.4.x 主要交付汉化、来源标签和 installer cache 修复。

v0.5

Checkpoint 与执行隔离

Git-aware checkpoint、恢复预览、ExecutionProvider、Linux bwrap/container 和资源策略。

P0/P1 · 8-10 周
安全

网络关闭、秘密显式 deny/mask、能力缺失拒绝，禁止自动降级。

门禁

Escape、symlink、socket、credential、进程树和资源耗尽测试。

后续事实

真实 0.5.x 主要交付深浅 TUI、主题安装修复和 Provider model seed。

v0.6

受控并行编排

Explorer/Worker/Reviewer、父子事件、独立 worktree、预算、失败传播和结果聚合。

P1 · 8-10 周
默认

探索、测试、审查可并行；修改默认单 worker。

写入

多 worker 仅在文件 ownership 可静态分区且用户显式启用时开放。

门禁

paired 实验同时判断墙钟、成功率、冲突率和总成本。

v0.7

GitHub 原生工作流与可选远程执行

Issue/PR 触发、专用分支、checks、artifact、review receipt 和 ephemeral runner。

P2 · 条件启动
非目标

不自动 merge、不跨仓库写、不长期保存 PAT、不默认联网。

启动条件

前序 SLO 连续稳定、威胁模型审查、权限/日志/incident owner 明确。

回退

条件不满足时只交付 GitHub Action，不建设托管控制面。

Data & gates

原数据与质量方案

旧方案不主张全量 event sourcing，而是保留 task snapshot 为执行真相，增加 append-only event、artifact、receipt 和 cursor-based control API。

对象 / 门禁原方案关键边界
Task snapshotschemaVersion、revision、owner、processIdentity、heartbeat、activeRunId。原子写；旧状态保守迁移。
TaskEventeventId、seq、runId、traceId、parentId、payloadRef 和 digest。单 writer、幂等、尾部半写恢复。
Receiptcommand、exitCode、startedAt、endedAt、verdict 和 artifact hash。大日志只存引用，默认脱敏。
可靠性故障注入、重启、取消和 owner 测试。重复执行、误杀或未知 owner 一票否决。
质量冻结任务集 paired 结果和置信区间。无法排除回归则默认关闭。
安全威胁模型、攻击测试、secret、closure 和 lifecycle。沙箱降级、凭据泄露或路径逃逸阻断发布。

Original recommendation

当时如果只做一件事

先交付事件协议、heartbeat、非交互增量日志、stuck diagnosis 和 execution receipt。这条判断推动了后续任务可观测与证据能力；新版战略则从 v0.5.2 出发，把首要问题更新为源码所有权、Provider 生命周期、stable-key i18n 和可持续上游同步。
