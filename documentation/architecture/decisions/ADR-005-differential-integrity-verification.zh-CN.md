# ADR-005：差分运行时完整性校验

```text
状态：拟用于 0.7.2
日期：2026-08-24
工作项：0.7.1 发布后维护（启动性能）
```

## 背景

每次 CoCo 启动都会依据内容寻址的清单校验运行时树（参考安装：21,369 个文件、
133 MB）。原设计有两项成本：

- 热路径对每个启动闭包文件执行 lstat/open/fstat/lstat 链（每文件四次系统
  调用），并为每次比较分配六个快照对象。
- 冷路径——缓存缺失、清单变更或首次运行——通过八次系统调用的读取助手重新
  读取并哈希全部 133 MB，且以逐目录串行递归遍历运行时根。

参考安装实测：热校验 2.8 秒，冷校验 6.8 秒，交互首屏约 4.5–5 秒。worker 线程
哈希实验实测 8.7 秒并被否决：冷路径受系统调用支配（对全部清单文件做一次无哈
希的串行读取就需要 2.8 秒），而非 CPU 受限，增加并发只会加剧争用。

## 决策

1. **差分冷校验。** 当存在与清单哈希完全匹配的已批准缓存时，六字段 stat
   （size、mtimeMs、ctimeMs、mode、dev、ino）仍与缓存快照一致的条目视为未
   变更，跳过重新哈希；其余条目回落到完整哈希。任何元数据漂移、缓存损坏或
   清单变更都会按文件禁用复用。
2. **元数据检查的系统调用瘦身。** 热路径从不读取文件内容，其每文件检查为
   前后两次 lstat（两次系统调用），取代 lstat/open/fstat/lstat；快照比较
   为无分配的字段比较。
3. **精简校验读取。** 内容读取使用 open(O_NOFOLLOW) 加读取前后对句柄的
   fstat（每文件五次系统调用）。哈希字节归属于已验证的 inode；读取之后的
   路径替换无法追溯改变该证据，因此刻意省略路径级重 lstat。
4. **并行元数据遍历。** 运行时根扫描使用仅 readdir 的 dirent 遍历，目录与
   缓存快照收集并发执行。

## 安全后果

- 任何环境变量或可伪造属性都不能绕过校验；差分快速通道以清单哈希为键，与
  既有热路径处于同一可信本地信任级别。
- 任何文件的任何元数据变化都会回落到该文件的完整哈希；缓存被删除或损坏将
  强制全量哈希。
- 各处保留符号链接拒绝：open 时的 O_NOFOLLOW、遍历时的 dirent 类型拒绝、
  每次 stat 的 isFile 检查。
- 快照 CAS 的复用契约（以内容哈希拒绝符号链接、损坏与身份漂移）刻意不动；
  运行时快照存储在复用时仍然重新哈希。

## 运维后果

实现后参考安装实测：热校验 1.3–1.5 秒（FAST）、冷校验 4.3 秒、更新后差分
校验 3.5–4.0 秒、交互首屏约 2.5 秒。缓存文件保持私有、原子替换并带模式版本。

## 已否决的替代方案

- worker 线程哈希（实测更慢；系统调用受限的负载）。
- 放宽快照 CAS 的复用（违反损坏拒绝不变量）。
- 只信目录拓扑而不做每文件元数据（丢失逐文件漂移回落）。
