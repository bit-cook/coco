# ADR-006：帧安全本地化缓存

```text
状态：拟用于 0.7.2
日期：2026-08-24
工作项：0.7.1 发布后维护（运行时性能）
```

## 背景

TUI 中每个可见的本地化字符串都经由 `uiText()` 解析，单帧渲染要本地化数十个
字符串（状态栏、快捷键提示、菜单、选择器标题）。区域设置解析器在**每次调
用**时用 `readFileSync` 读取并解析 `language.json`：每个字符串约 30–80 微秒
的阻塞式主线程磁盘 IO，按每帧四十个字符串计约 0.29 毫秒同步 IO。token 流式
输出期间渲染循环持续运行，这部分 IO 直接挤占帧预算，并与上游渲染开销叠加。

模拟真实负载（3,000 帧 × 每帧 40 次本地化调用）实测旧实现纯解析耗时
875 毫秒。

## 决策

`uiLocale()` 维护单条自失效缓存：每次调用执行一次 `statSync`，只要
`(path, size, mtimeMs)` 不变即复用缓存区域设置；元数据变化时才重新读取并解
析一次。文件缺失时每次调用回落到环境区域设置（一次失败的 stat，不缓存负结
果），因此首次 `/language` 写入会被立即感知。

## 安全后果

无。缓存只保存区域设置字符串与用户自身选择文件的 stat 签名；它不能绕过完
整性校验，`/language` 命令的持久化语义不变（选择文件仍是唯一事实来源，任何
元数据变化都会触发重读）。

## 运维后果

实测：100,000 次 `uiLocale()` 调用耗时 480 毫秒（每次 4.8 微秒）；模拟帧负
载的阻塞 IO 从每帧 0.29 毫秒降至 0.10 毫秒（2.9 倍）。由于写入会更新
`mtimeMs`，`/language` 切换仍然即时生效。

## 已否决的替代方案

- TTL 缓存：`/language` 切换后可能在一个 TTL 窗口内渲染过期区域设置。
- 事件式失效：把语言服务与 UI 层耦合，且无法感知对 `language.json` 的外部
  编辑。
- 缓存完整译文：用户语言包每次重载都会失效，且动态输入下无界增长。

## 测试

- test/coco-language.test.mjs —— 语言服务套件 6/6，覆盖中英切换、持久化与损坏语言包回落。
- 模拟帧负载基准记录于日志：3,000 帧 × 40 次调用，解析器阻塞 IO 每帧 0.29 毫秒降至 0.10 毫秒；100k 次 uiLocale 调用 480 毫秒。
