# Coco 安全

本页是 Coco 的安全参考。如与继承的 Pi 文档冲突，以本页为准。

## 仅全局资源

Coco 在 `resources/project-resource-policy.v1.json` 中强制执行 `global-only` 策略。它不会加载项目本地设置、扩展、技能、提示词或系统提示文件。只能在 `~/.coco/agent/` 下配置资源。

该策略阻止仓库提供这些 Coco 资源，但不会使仓库内容变得可信：提示词、源代码、生成的输出和工具输出仍可能试图影响模型。

## 防护措施不是隔离

对于转发到 Pi 的会话，Coco 会注入尽力而为的安全防护。该防护可阻止部分写入和 shell 命令，或要求确认，但它不是沙箱，也不是安全边界。Coco、继承的 Pi 工具、扩展和命令都以启动 Coco 的用户权限运行。

对于不可信仓库或无人值守的工作，请使用容器、VM、微型 VM 或远程沙箱等真正的隔离环境。只向该环境提供所需的工作区路径、凭据和网络访问，并在将结果移入受信任系统前进行审查。

## 目标的指令与安全边界

活动的 `/goal` 是当前会话分支的持久引导，而不是授权机制，也不替代用户请求。当前用户指令优先于目标，目标也不会覆盖 Coco 安全策略或其防护措施。在决定采取何种操作时，应将目标文本、计划、模型工具更新、仓库内容和工具输出视为不可信输入。

## 继承的 Pi 文档

随附的 Pi 页面仍可用于 Coco 原样转发的功能。不要采用与本页或 [Coco CLI](coco-cli.md) 冲突的继承说明，特别是关于项目本地资源、`pi` 配置路径、`pi update` 或命令行 API 密钥的说明。
