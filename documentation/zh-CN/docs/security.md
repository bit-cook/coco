# 安全

Pi 是一个本地编码代理。它以启动它的用户账户权限运行，并将该用户可写的文件视为同一本地信任边界内的内容。

## 项目信任

项目级信任控制 pi 是否加载项目本地的设置、资源、包和扩展。它不是沙箱，也不会限制你开始在某个目录中工作后模型可以要求工具执行的操作。

当 pi 从当前工作目录发现以下任一项时，会将项目视为包含需要信任的资源：

- `.pi/settings.json`
- `.pi/extensions`、`.pi/skills`、`.pi/prompts` 或 `.pi/themes`
- `.pi/SYSTEM.md` 或 `.pi/APPEND_SYSTEM.md`
- 当前目录或祖先目录中的项目 `.agents/skills`

单独存在的 `.pi` 目录不算作需要信任的项目资源。

当交互式会话在包含需要信任资源的项目中启动，且当前目录或父目录没有保存的决定时，pi 遵循全局设置中的 `defaultProjectTrust`。默认值为 `"ask"`，在界面可用时会询问是否信任该项目。保存的决定按规范目录存储在 `~/.pi/agent/trust.json` 中。在应用全局默认值之前，会优先采用当前路径或父路径上最近保存的决定。

信任项目后，pi 可以加载需要信任的项目资源，包括：

- `.pi/settings.json`
- `.pi` 资源，例如扩展、技能、提示模板、主题和系统提示文件
- 通过项目设置配置但缺失的项目包
- 项目本地扩展和由项目包管理的扩展

拒绝信任会跳过受保护的资源。无论项目是否受信任，都会加载 `AGENTS.md` 和 `CLAUDE.md` 上下文文件，除非已禁用上下文加载。在信任决定确定之前，pi 只加载上下文文件、用户或全局扩展以及 CLI `-e` 扩展。用户或全局扩展和 CLI 扩展可以处理 `project_trust` 事件；第一个返回是或否决定的扩展拥有该决定权。

非交互模式（`-p`、`--mode json` 和 `--mode rpc`）不会显示信任提示。在没有适用的已保存信任决定时，`defaultProjectTrust: "ask"` 和 `"never"` 会忽略此类资源，而 `"always"` 会信任它们。使用 `--approve`/`-a` 或 `--no-approve`/`-na` 可以为单次运行覆盖项目级信任设置。

## 没有内置沙箱

Pi 不包含内置沙箱。内置工具可以以 pi 进程的权限读取文件、写入文件、编辑文件和运行 shell 命令。扩展是以相同权限运行的 TypeScript 模块。包安装、shell 命令、语言服务器、测试命令和其他开发工具都作为普通本地进程运行。

这是有意为之的。Pi 的设计目标是在本地源代码树上工作、调用项目工具链，并集成用户现有的开发环境。进程内的部分沙箱很容易被误解为安全边界，但它仍然依赖主机 shell、文件系统、包管理器、凭据和扩展代码。真正的隔离必须来自操作系统或虚拟化、容器边界。

项目级信任仅是输入加载保护。它会在你批准仓库前，防止仓库悄悄更改 pi 的设置或扩展。但它不会让不受信任的代码、不受信任的提示或不受信任的模型输出变得安全。来自仓库文件、注释、文档、上下文文件或构建输出的提示注入属于本地代理的预期风险，pi 无法可靠地阻止它。

## 运行不受信任或无人监控的工作

对于不受信任的仓库、不打算密切监控的生成代码，或无人值守的自动化任务，请在受隔离的环境中运行 pi。使用容器、VM、微型 VM、远程沙箱或策略控制的沙箱，并且只提供任务所需的文件和凭据。

常见模式记录在[容器化](containerization.md)中：

- 在容器或沙箱内运行整个 `pi` 进程
- 在主机上运行 pi，同时将内置工具执行路由到 Gondolin 微型 VM
- 只挂载代理应访问的工作区路径
- 除非容器需要访问主机的会话、设置和凭据，否则不要挂载主机的 `~/.pi/agent`
- 传入所需的最少 API 密钥，或使用短期凭据
- 任务不需要网络时限制网络访问
- 将结果复制回受信任系统前，先审查差异和输出

如果以读写方式绑定挂载主机工作区，容器或 VM 内的写入仍然可以修改主机文件。需要更强的意外写入防护时，请使用只读挂载，或将文件复制进出沙箱。

## 报告安全问题

要报告安全问题，请遵循仓库的[安全策略](https://github.com/earendil-works/pi-mono/blob/main/SECURITY.md)。不要为涉及安全敏感内容的报告创建公开 issue。

预期的本地代理行为、缺少内置沙箱、来自不受信任内容的提示注入，以及用户安装的扩展或技能的行为，通常都在安全边界之外，除非报告证明存在真正的权限边界绕过，或说明 pi 如何授予本地用户原本没有的访问权限。
